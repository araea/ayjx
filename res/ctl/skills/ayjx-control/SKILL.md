# 控制 ayjx 自身

本轮（且仅本轮）你可以直接读写这台机器人的插件配置，命令以维护者身份执行。
凭据已经放在环境变量里，命令行入口：

```bash
"{{AYJX}}" --ctl "list"
```

一次一条命令，stdout 就是管理员在聊天里执行 `/ctl` 会看到的同一段回执；
命令被拒绝或出错时退出码非零，错误同样打在 stdout。

## 命令

去掉 `/ctl` 前缀，把剩下的部分原样传进来。

| 命令 | 作用 |
| --- | --- |
| `list` | 所有插件与开关状态 |
| `list on` / `list off` / `list 统计` | 按状态或名称筛选 |
| `show <插件>` | 当前完整配置 |
| `show <插件> <路径>` | 查看嵌套字段，如 `show ciyi plugin.image_scale` |
| `defaults <插件>` | 默认值 |
| `diff <插件>` | 与默认值的差异 |
| `on <插件> [插件...]` | 开启，可一次多个 |
| `off <插件> [插件...]` | 关闭 |
| `set <插件> <路径> <值>` | 改配置，值用 TOML 语法 |
| `reset <插件> [路径] --confirm` | 恢复默认 |

`set` 的值：布尔写 `true`/`false`（或 `开`/`关`），数组整体替换写
`[123456, 789012]`，单个元素写 `channel.white.0 456789`，整张表写
`channel { white = [123456], black = [] }`，字符串可含空格，清空写 `""` 或 `[]`。
配置路径以点分隔，只能改已有路径。

## 规矩

- 改之前先 `show`，改完再 `show` 或 `diff` 复核，把关键差异用一句话告诉用户。
- 一次只改一个字段；要批量开关插件就用一条 `on a b c`，不要连发。
- 别碰 `ctl.admins`，也别试图关掉 `ctl` 自己——会被拒绝，那是保命的入口。
- 你替所有人操作同一台机器人：改动会影响别的群和别人。涉及推送目标、白名单、
  API 密钥这类会波及他人的字段，先把要改什么说清楚，等对方确认再动手。
- 凭据只在本轮对话内有效：不要写进文件、不要打印、不要发到群里，也不要试图
  自己去改 `config.toml`——运行中的实例会在退出时用内存里的配置覆盖它。
- 命令失败就把原文错误转述给用户，不要换个写法反复重试。
- 用户只是问「某插件是什么/怎么用」时，用 `list`、`show` 看一眼就够，不要顺手改。
