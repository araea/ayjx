# 群聊搭话

`oai` 插件的一个可选能力：让本机 pi agent 以一个固定人格作为群成员之一存在，
读群聊、极少数时候开口。默认关闭，只在 `[oai.ambient].groups` 列出的群里生效。

## 三段式

```
群消息 → 滚动窗口 ──安静下来──→ 判定模型（便宜、能看图）
                                        │ 分数 < 阈值 → 什么都不发生（常态）
                                        ↓ 分数 ≥ 阈值 或 被 @
                                   本机 pi（人设 + 工具 + skill）
                                        │ [silent] → 仍然不发
                                        ↓
                                   按行拆条 → 按打字速度错开发出
```

- **听**：进入 `oai` 而没被任何指令消费的群消息都进内存窗口（每群 80 条），
  窗口就是模型能看到的全部上下文，不落库，重启即空。机器人自己发出的话也回填
  进窗口，因此它知道自己刚说过什么。
- **判**：群里静默 `debounce_seconds` 秒后判定一次，一串刷屏只判一次；
  判定失败若属于网络抖动（超时、连接被对端关闭、5xx）会隔 2 秒重试一次——判定是
  整条链路的入口，一次抖动等于这一轮群聊没人看过；模型拒收内容这类错误立刻放弃；
  图片先转成模型收得下的格式（GIF 表情包取首帧转 PNG，过大的缩到 1024 边长）——
  一张表情包不该让整轮判定失败；
  最多等 `max_wait_seconds` 秒就必须判。判定模型只回
  `{"score": 0-100, "reason": "…"}`，附带最近 `context_images` 张图片，
  因此它读得懂表情包和截图。分数只写进日志。
- **说**：过线才唤起 pi（`--no-session`，上下文就是那段聊天记录），
  带人设、工具白名单与描述 Satori 消息元素的 skill。产出按行拆成消息。

判定与措辞分开，是因为二者的成本与失败方式不同：判定要便宜、要频繁、要能看图；
措辞要慢、要少、要有工具。合成一次调用只会两头将就。

## 沉默的四道闸

按顺序，任何一道都能让这一轮归于安静：

1. 说话的是自己、是指令、或消息为空 → 连判定都不安排；
2. 窗口最后一句是自己说的（没人接话就不自说自话）、每小时上限已满、
   或距上次发言不足 `cooldown_seconds`（被 @ 时不受此限）；
3. 判定分低于当时的门槛（见下）；
4. 人格模型自己输出 `[silent]`——人设保留随时闭嘴的权利，这一条经常发生。
   唯一的例外是被直接 @：那一轮会明确告诉它「可以敷衍、可以一个反问打发，
   但除非话题落在禁区里，别一字不回」——被点名却一声不吭，看着不像孤傲，像挂了。

## 门槛会随沉默下移

固定门槛下的人格只有两种结局：要么天天说话，要么再也不说话——群聊的话题分布是稳定的，
而门槛不动。所以门槛按沉默时长缓慢下移：每 10 分钟没开口降 `silence_relief_per_10min`
分，最多降 `silence_relief_cap` 分。

于是「大多数时候沉默，偶尔搭一句」成了能自己维持的节奏：刚说完话时挑剔（45 分），
沉默半小时后连日常闲聊（判定约 30 分）也接得住，说完一句又回到挑剔。
想更爱说话就调低 `score_threshold`，想更孤僻就调低 `silence_relief_cap`。

## 输出协议

模型的输出按行读取，一行就是一条 QQ 消息，最多 `max_messages` 条。
行内 `[at:QQ号]`、`[face:表情ID]`、`[img:直链]`；独占一行的
`[poke:QQ号]`、`[dice]`、`[rps]`、`[wait:秒数]`、`[silent]`。
不认识的方括号原样发出（群友本来就会打 `[笑]`）。

完整的元素说明写在 skill 里，模型需要时自己读：
`data/oai/ambient/skills/satori-reply/SKILL.md`。要扩展回复花样，改这个 skill，
不必动 Rust——它每次启动都从仓库的 `res/ambient/` 覆盖，请在仓库里改。

## 拟人的节奏

每条消息发出前都要「打」出来：`typing_cpm` 是逐字打字速度，长句按
`voice_cpm` 的语音输入速度折算（一口气说完再转写，字均更快），上下随机浮动 30%，
单条至少 1.2 秒。开口前另有 `think_seconds` 的思考停顿，模型本身花掉的时间计入
其中——想了 10 秒的回答不会再假装犹豫。条与条之间约 1 秒换气，
模型也可以用 `[wait:n]` 自己加停顿。

## 人设

`data/oai/ambient/persona.md`，首次启动从 `res/ambient/persona.md` 落盘，
**之后不再覆盖**：人设是要反复打磨的东西，改一句不该等一次编译。
想恢复内置版本就删掉这个文件重启。

## 配置

`config.toml` 的 `[oai.ambient]` 段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 总开关 |
| `groups` | `[]` | 开启搭话的群号；空列表等于不开启 |
| `gate_model` | `gemini-3.5-flash-lite` | 判定模型，走 `oai` 已配置的接口与密钥 |
| `reply_model` | `apilio/gemini-3.8-flash` | 发言模型，交给 pi 的 `provider/model` |
| `thinking` | `low` | 发言模型的思考强度 |
| `tools` | `read,bash,web_search,fetch_content,get_search_content` | 发言时开放的工具白名单 |
| `score_threshold` | `45` | 开口意愿分门槛，调高更沉默 |
| `silence_relief_per_10min` | `5` | 每沉默 10 分钟门槛下调的分数 |
| `silence_relief_cap` | `20` | 沉默补偿上限 |
| `context_turns` | `20` | 送进模型的最近消息条数 |
| `context_images` | `2` | 随上下文送进模型的最新图片张数；`0` 关闭图片判读 |
| `debounce_seconds` | `5` | 群里安静这么久之后才判定 |
| `max_wait_seconds` | `30` | 最多等这么久就必须判定一次 |
| `cooldown_seconds` | `90` | 两次发言的最短间隔；被 @ 时不受限 |
| `hourly_limit` | `12` | 每群每小时发言上限 |
| `reply_on_mention` | `true` | 被 @ 时跳过判定直接开口 |
| `max_messages` | `3` | 一次最多拆成几条消息 |
| `typing_cpm` | `150` | 打字速度（字/分钟） |
| `voice_cpm` | `420` | 长句折算的语音输入速度（字/分钟） |
| `think_seconds` | `3.0` | 开口前的思考停顿 |
| `gate_timeout_seconds` | `45` | 判定超时 |
| `reply_timeout_seconds` | `240` | 一次发言（含工具调用）超时 |

判定模型复用 `oai` 的 API 地址与密钥（`智能体 <地址> <密钥>` 设置的那一份）；
发言模型的凭据在 pi 侧配置，不经由 ayjx。

## 注意

- 工具白名单里的 `bash` 是真的本机 shell，与 `pi` 房间同权限。不希望群聊触发命令
  执行就把它从 `tools` 里去掉，其余能力不受影响。
- 一个群同一时刻只有一次判定或发言在跑，发言期间的新消息只进窗口。
- 判定与发言都有超时；发言超时会连同 pi 派生的工具进程一起终止。
