# 内置 Agent 房间

`oai` 插件可以把任意房间交给一个内置 agent。它自己调用模型和工具，把事情做完再回一句话。不需要额外安装任何东西，模型接口沿用 `[oai.providers]` 里的配置。

引擎是房间自己的属性，与名字无关：

| 指令 | 效果 |
| --- | --- |
| `##研究 pi` | 新建一间 agent 房间，模型取 `agent_default_model` |
| `##研究 pi/deepseek/deepseek-flash` | 新建并指定模型 |
| `研究%pi` | 把已有房间转成 agent 房间 |
| `研究%pi apilio/kimi-k3` | 换这间房用的模型 |
| `研究%gpt-5.6-luna` | 转回中转站房间 |

`pi` 后面用空格、`/` 或 `:` 分隔模型都可以，大小写不限，房间名不受限制。

## 供应商与思考强度

普通（中转站）房间的模型可以写成 `供应商/模型`，按供应商路由到不同接口：

| 指令 | 效果 |
| --- | --- |
| `##助手 deepseek/deepseek-flash` | 建一间走 DeepSeek 官方接口的房间 |
| `助手%apilio/gpt-5.6-luna` | 换回 apilio 中转站 |
| `助手%deepseek/deepseek-flash:high` | 换模型并顺带设思考强度 |
| `##助手 deepseek/deepseek-flash:low` | 建房时直接指定强度 |

供应商在 `[oai.providers]` 里定义（`api_base` + `api_key`）。`apilio` 是历史默认接口，即使不单独配置也始终回退到 `[oai]` 那一份（`oai <url> <key>` 配的），不需要重复填写；未知供应商会明确报错，不会静默打到别的站点。不带前缀的模型仍走默认接口，行为不变。

agent 房间与普通房间走同一套解析：房间模型是 `供应商/模型` 时按前缀取接口，也可以只写 `pi` 或留空，表示使用 `[oai] agent_default_model`。

思考强度取 `off` / `minimal` / `low` / `medium` / `high`（`xhigh` 也认），有两种写法：模型后的 `:强度` 后缀优先，其次是房间自己的 `thinking` 字段。agent 房间与普通房间都把它转成请求里的 `reasoning_effort`，留空表示交给引擎默认值。`/#` 与回执里会标出 `· 思考:强度`。

早先只有名为 `pi` 或 `pi-*` 的房间才能使用这套 agent，所有想用它的房间都被迫带着这个前缀。现在引擎写在房间自己身上（配置里的 `engine` 字段），首次启动时按当初的名字规则一次性写好，已有房间的行为不变，此后名字改成什么都不影响引擎。`-` 仍不能出现在新房间名里（`助手-1` 是「删除第 1 条」的写法），历史上的 `pi-*` 房间是唯一例外，继续放行。

## 行为

一轮对话就是一个工具循环：把房间历史展开成消息发出去，模型需要工具就执行、把结果回填，直到它不再需要工具。因此：

- 公有、私有、临时三种模式各自隔离历史。改写历史或重新生成直接生效，历史始终由 ayjx 侧持有，没有第二份会话文件可以不一致
- 房间提示词追加在内置系统提示词之后。系统提示词本身只说工作目录与手边有什么
- 正文与图片按多模态消息发出。中间的工具调用与思考不写入聊天记录
- 回复卡片页脚显示实际模型、耗时与工具调用轨迹。不含标题、列表或代码块的短回复直接发文本，不渲染图片
- 停止或超时会终止正在运行的工具进程，包括 bash 派生的独立进程组
- 模型接口不可用、工具步数超过上限都作为对话失败返回，不影响其他房间

## 工具

agent 手边有两类工具。本地工具在房间里默认全开：

| 工具 | 作用 |
| --- | --- |
| `bash` | 在房间工作目录里执行命令，默认 120 秒超时、可用参数延长到 600 秒，输出过长从中间省略 |
| `read` | 按行号读文本文件，支持 offset/limit |
| `write` | 整份写入文件，自动建父目录 |
| `edit` | 精确替换一段原文；命中多处或找不到会明确报错 |
| `glob` | 按通配符找文件 |
| `grep` | 按正则搜索文件内容 |

聊天界面工具只在群聊搭话时存在（详见[群聊搭话](ambient.md)）：`satori_context`、`satori_read`、`satori_action`、`satori_draw`、`satori_history`、`satori_group`、`satori_memo`。它们直接调用进程内的通道，动作、额度与回执去重都由插件负责。

联网工具由 `[oai.search].enabled` 控制，默认关闭（群聊搭话那边默认开着）：

| 工具 | 作用 |
| --- | --- |
| `web_search` | 搜一次，返回带序号的标题、链接与摘要；`recency` 可限定最近一天/一周/一月/一年 |
| `web_fetch` | 读一个网址的正文并转成纯文本；只支持公网 http/https，内网与本机地址会被拒绝 |

后端、超时、每轮次数上限与密钥都在 `[oai.search]` 里配置一次，房间与搭话共用。默认使用免密钥的 Bing 和 DuckDuckGo 抓取，不需要配置即可使用。要更稳或更好的中文覆盖，可以在 `[oai.search.backends]` 里补 `tavily` / `brave` / `serper` 的密钥，或指向自建的 `searxng`。默认按 `providers` 的顺序依次尝试，前一个失败就顺延，全部失败会明确报错。Bing 中文站对空格敏感，发出去之前会先收紧汉字之间的空格。检索到的来源会渲染在回复卡片下方，回答里也要求带上链接。

`web_fetch` 沿用 `[webshot]` 那套链接准入：搜索结果是不可信输入，模型可能被网页里的一句话指使去读本机面板，所以主机先解析再判定，重定向逐跳复检。

## 联网是按需的

开启出网工具不等于每轮都去搜索。系统提示词里写的是「只在回答站不站得住取决于新信息时才用」：赛程战况、版本改动、新闻、近况这类要查，日常闲聊、能算能推的、模型本来就知道的照旧直接答。工具描述里也点明了同一条，模型随时可以不搜索。

每间房自己开关，符号是 `?`（一个问句的收尾，比别的都好记）：

| 指令 | 效果 |
| --- | --- |
| `研究?` | 换一边：关着就开，开着就关 |
| `研究?开` / `研究?on` | 这间房打开（`开`/`打开`/`联网` 也认） |
| `研究?关` / `研究?off` | 这间房关闭（`关`/`关闭`/`不联网` 也认） |
| `研究?默认` | 交回 `[oai.search].enabled`（`默认`/`auto`/`跟随` 都认） |

状态有三态：没写过的房间跟着全局走，写过 `开` / `关` 的房间就认自己那一份，管理员之后翻全局开关也不影响它。回执会说明是「已打开（按需触发）」还是「跟随全局（当前关）」，并顺带报告会打到哪些后端。`/#` 列表里开了联网的房间带一个 🔍，`研究/$` 也会显示当前状态。不是内置 agent 的房间用不了，会提示先 `房间%pi` 转过来。

这里没有沙箱：`bash` 能做的事，工具集里其他方式也能做到。边界在「谁能在房间里说话」这一层，不在工具本身。

agent 房间还带一份 skill，说明怎么用 `ayjx --ctl` 操作机器人自身。凭据只在发起人是 `ctl.admins` 里的管理员时随这一轮签发，见[插件控制](CONTROL.md)。

## 画图预设房间

一组开箱即用的绘图房间，首次启动时自动建好，在 `/#` 的「画图预设」分区里单独成组。名字一律是 `画·<风格>`，中间那个 `·` 是为了不被日常聊天误触发——房间指令按前缀匹配，房间叫「手办」的话，任何以「手办」开头的闲聊都会被当成绘图指令。

| `画·盲盒` | 盲盒公仔与包装盒 |
| `画·RPG卡` | RPG 角色属性卡 |
| `画·四格` | 四格漫画，带点幽默 |
| `画·简笔` | 手绘简笔画表情系列 |
| `画·复古广告` | 红黄放射的复古促销海报 |
| `画·CCD` | CCD 老数码相机的自拍 |

引擎上它们不是内置 agent 房间，而是走图像接口的普通房间：房间的系统提示词是风格前缀，用户那句话接在后面，两段一起交给图像接口（见 `src/plugins/oai/presets.rs` 与 `images.rs`）。所以「预设」不需要任何新机制，它就是一间系统提示词写得足够好的房间，改起来和别的房间没有区别。

- 用法：`画·手办 一只戴眼镜的橘猫`
- 垫图：直接发一张图、引用一张图，或在房间名后 @某人，再补一句修改要求；合计最多 4 张
- 可选参数：`--size 1536x1024`（或 `-s auto`）、`--quality high`（或 `-q low/medium/high/auto`）
- 加 `~` 前缀（`~画·手办 ...`）不留历史
- 提示词就是房间的系统提示词：`画·手办/$` 看一眼，`画·手办$自己的提示词` 改掉，`画·手办~#我的手办` 复制一份再改
- 删掉的房间不会在下次启动时复活；新增预设只补建没见过的那几间，不动已有房间的模型与提示词

建房间时按 `[oai].image_models`（默认 `["gpt-image-2.5"]`）在站点上选一个在售的 id，模型列表还没拉回来时用兜底 id。图像接口、尺寸与画质参数与手写的图像房间完全一致。

## 音乐房间

写歌用的是中转站的 Suno 接口（`/suno/submit/music` 提交、`/suno/fetch/{id}` 查进度）。房间模型关键字命中 `[oai].music_models`（默认 `["suno"]`）就自动走这条路，和画图预设同一套写法：系统提示词是风格描述，用户那句话是主题，两段拼起来交给 Suno。

首次启动时自动建好，在 `/#` 的「音乐房间」分区里，名字是 `歌·<风格>`。

| 房间 | 写什么 |
| --- | --- |
| `歌·随写` | 一句话生成一首歌 |
| `歌·国风` | 国风：古筝笛子配现代编曲 |
| `歌·民谣` | 民谣：木吉他、近麦人声 |
| `歌·电子` | 电子舞曲：四拍底鼓与合成器 |
| `歌·说唱` | 中文说唱：boombap 鼓组 |
| `歌·纯音乐` | 纯音乐，全程无人声 |

- 用法：`歌·民谣 唱一首关于秋天落叶的歌`
- 可选参数：`--标题 名字`、`--风格 folk,acoustic`、`--版本 chirp-v5`、`--纯音乐`
- 正文写成 `[Verse]` / `[Chorus]` 那样的歌词体裁时按自定义模式提交（正文就是歌词，`--风格` 才有用），否则按灵感模式提交（正文是创作描述，歌词由 Suno 自己写）
- 一次提交出两个版本，两个都发：封面走图片段，音频按 `[oai].music_send` 决定发语音气泡还是群文件（默认 `both`，先发群文件再补一条语音）
- 回复正文里有歌名、时长、风格标签、版本与这一单的花费，后面跟一句歌词引子
- 加 `~` 前缀（`~歌·民谣 ...`）不留历史

版本写 `chirp-v5` 拿到的就是站点当前最新的一档（实测回包是 `major_model_version: v6`、`model_name: chirp-hawk`）；站点接上更新的版本时改 `[oai].music_version`，不必改代码。

## 视频房间

拍片走中转站的 OpenAI 视频任务接口：`POST {base}/video/generations` 拿任务号，`GET {base}/video/generations/{id}` 轮询到 `video_url`，最后把整段视频当一个视频消息发出去。房间模型关键字命中 `[oai].video_models` 就自动走这条路。

首次启动时自动建好，在 `/#` 的「视频房间」分区里，名字是 `影·<风格>`。

| 房间 | 拍什么 |
| --- | --- |
| `影·通用` | 按你描述拍一段 |
| `影·电影感` | 电影质感与运镜 |
| `影·动画` | 手绘二维动画风 |
| `影·广告` | 广告级产品镜头 |

- 用法：`影·电影感 一只橘猫坐在窗台上看雨`
- 可选参数：`--秒数 8`（默认取 `[oai].video_seconds`，5 秒；veo3.1 这一档实际由上游定，写 5 也会按 8 秒出）、`--竖屏` / `--横屏`（默认横屏 16:9）、`--尺寸 1280x720`
- 一次生成通常一两分钟，所以这类房间用 `[oai].media_timeout_seconds`（默认 900 秒）而不是 `request_timeout_seconds`
- 回复正文里有用户那句话、时长、模型与这一单的花费（写作纯文本，不渲染卡片）

默认预设用的是 `veo3.1-fast`：同一套接口上实测跑得通、自带同步音效、出片约一分钟、一次约 $1.2，是这批顶级模型里性价比最高的一档。别的模型用 `房间%模型` 换过来即可，但各家渠道的分组、单次价格与所需参数并不一样，换之前先确认能调通：

| 模型 | 实测情况 |
| --- | --- |
| `veo3.1-fast` / `veo3.1-pro` | 走 `/v1/video/generations`，约一分钟出片，自带音效 |
| `wan3.0-video-prime` | 同一套接口可用，但一次约 $9，等待约三分钟 |
| `doubao-seedance-2.5` | 同一套接口返回 `upstream_error`，官方格式是另一条路径（`/seedance/v3/...`） |
| `kling-video-v3` | 该分组不支持 `/v1/video/generations`，要用可灵自己的路径 |
| `grok-video-3` | 当前令牌的分组里没有可用渠道 |

## 配置

位于 `config.toml` 的 `[oai]` 段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `agent_default_model` | `deepseek/deepseek-flash` | 房间没写模型（留空或 `pi`）时用它；留空则退到 oai 的默认模型 |
| `request_timeout_seconds` | `300` | 单次回复的总时间预算 |
| `pi_stall_seconds` | `180` | 单次模型请求静默这么久算卡死；卡住且没动过工具时自动重来一次，`0` 关闭 |
| `plain_text_max_chars` | `120` | 短回复的纯文本阈值，`0` 表示始终渲染图片 |
| `show_trace_footer` | `true` | 是否在卡片页脚显示模型、耗时与工具轨迹 |
| `image_models` | `["gpt-image-2.5"]` | 走图像接口的模型关键字（子串匹配），画图预设房间据此选在售 id |
| `music_models` | `["suno"]` | 走 Suno 文生歌的房间模型关键字 |
| `music_version` | `chirp-v5` | 提交 Suno 时的 `mv` 字段 |
| `music_send` | `both` | 生成的歌怎么发进群：`file` / `voice` / `both` |
| `video_models` | 见 `config.example.toml` | 走 OpenAI 视频任务接口的房间模型关键字 |
| `video_seconds` | `5` | 没写 `--秒数` 时的默认时长（1–30 秒） |
| `media_timeout_seconds` | `900` | 音乐、视频这类异步任务房间的等待上限 |
| `providers` | 空 | 供应商表，每项含 `api_base` 与 `api_key` |
| `search.enabled` | `false` | 没单设过的房间的默认值；每间房用 `房间?` 自己定 |
| `search.providers` | `["auto"]` | 搜索后端顺序；`auto` 展开成配置好的密钥后端（优先）加免密钥抓取（后备） |
| `search.max_uses` | `4` | 一轮对话里搜索与抓取加起来的上限 |
| `search.results` | `8` | 每次搜索最多返回几条 |
| `search.backends` | 空 | 各后端的 `api_key`（tavily/brave/serper）或 `base_url`（searxng） |

一次模型请求发出去之后要到收尾才有回复，中间没有事件可看，所以 `pi_stall_seconds` 是单次请求的上限：上游异常时请求会一直挂着，静默超过这个秒数就中止并重来一次。动过工具之后不再重试，同一份副作用做两遍比慢一点糟糕得多。

卡片渲染依赖 Chrome/Chromium，渲染失败时回退纯文本。等待期间不发进度提示，因为进度提示不会让回复更快，只会在群里插入与当前话题无关的内容。

同一个 agent 还可以作为群成员之一旁听群聊、偶尔搭话，见[群聊搭话](ambient.md)。
