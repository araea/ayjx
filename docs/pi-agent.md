# Pi 房间

`oai` 插件把名为 `pi` 或以 `pi-` 开头的房间接到本机 Pi CLI，模型、工具与鉴权全部
沿用 Pi 自身配置。房间名不区分大小写并忽略首尾空白；`ping`、`pixi`、`api` 等不匹配。

## 行为

- 公有、私有、临时三种模式各自隔离会话；改写历史或重新生成会重建对应的 Pi 会话。
- 房间模型即 Pi 的 `--model`：`/oai` 改房间模型立刻生效，支持 `provider/id` 与
  `id:thinking` 写法（如 `apilio/gemini-3.8-flash:low`）。留空或填 `pi` 表示沿用
  Pi 自身配置，卡片页脚显示「Pi 本机配置」。
- 房间提示词追加到 Pi 的系统提示词之后。
- 正文经 stdin 传入，图片写入临时文件传入，调用结束后清理。中间思考与工具输出不写入
  聊天记录。
- 回复卡片页脚显示实际模型、耗时与工具调用轨迹；不含标题、列表或代码块的短回复直接
  发送文本，不渲染图片。
- 停止或超时会终止 Pi 及其调用树内的工具进程，包括 Pi 通过 bash 派生的独立进程组。
- CLI 启动失败或非零退出作为对话失败返回，不影响其他房间。

## 配置

位于 `config.toml` 的 `[oai]` 段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `pi_command` | `pi` | Pi 可执行文件路径或命令 |
| `request_timeout_seconds` | `300` | 单次回复的总时间预算 |
| `pi_stall_seconds` | `90` | 事件流静默这么久算卡死；卡住且没出正文时自动重来一次，`0` 关闭 |
| `plain_text_max_chars` | `120` | 短回复的纯文本阈值；`0` 表示始终渲染图片 |
| `show_trace_footer` | `true` | 是否在卡片页脚显示模型、耗时与工具轨迹 |

Pi 自己不给模型请求设超时：上游抽风时它会安静地卡在网络等待上，直到总预算耗尽
（实测 5 分钟墙钟只烧 2 秒 CPU）。事件流是它还活着的证据，所以静默超过
`pi_stall_seconds` 就掐掉重来一次；已经吐出正文之后再卡，则直接把已有的交出去，
不让用户等第二遍。

模型、API 与工具在 Pi 侧配置，不经由 ayjx。卡片渲染依赖 Chrome/Chromium；渲染失败时
回退为纯文本。等待期间不发任何进度提示——一条播报换不来更快的回复，只会在群里插进
一段与上下文无关的噪音。

发起人是 `ctl.admins` 里的管理员时，这一轮对话还可以用自然语言操作机器人自身的插件
开关与配置，见[插件控制](CONTROL.md#在-pi-房间里用自然语言操作)。

同一个 Pi Agent 还可以作为群成员之一旁听群聊、偶尔搭话，见[群聊搭话](ambient.md)。
